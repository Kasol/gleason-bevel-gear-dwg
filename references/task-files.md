# 任务文件管理

1. `.result/`、`.template/`、用户输入和历史交付只读使用。新交付放在宿主输出位置，默认 `outputs/<本次唯一标识>/`；不复用旧任务目录、不覆盖文件，不要求技能目录可写。
2. 固定交付脚本会创建唯一任务目录；使用原生工具时先确认新目录和目标不存在。最终文件分别名为 `二维成品图.pdf`、`控制计划.xlsx`，并核对与指定源 SHA-256 一致。详细步骤只以 [交付规则](execution.md) 为准。
3. 如读取资料确需临时文件，集中到本次独立临时目录，记录此次创建的实际路径及用途；不往用户资料或技能目录写缓存。不为交付额外创建清单、报告、预览或备用版本。
4. 完成、失败或取消时，检查路径归属后只删除本次记录的临时文件和失败半成品，再删除已空的本次临时目录。出现未记录内容则保留，不递归清空共享目录，不删除其他任务进程、缓存或依赖。
5. 收尾确认最终文件仍可读取且内容未变；只链接最终交付物。清理失败如实指出残留，不声称已清理。不主动向业务用户解释内部清理机制。
