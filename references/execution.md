# 默认交付规则

## 1. 收集必要输入

业务不明时提供“二维成品图／控制计划”选项；二维出图方式不明时提供“上传草图／直接参数”。明确后不重复菜单。

| 业务 | 必要输入 |
|---|---|
| 有草图出图 | PDF／DWG／DXF 草图，以及用户提供或图中可用的齿形资料 |
| 无草图出图 | 几何参数、齿形参数、技术要求 |
| 控制计划 | 成品 PDF、工艺路线／过程图 Excel |

已提供的不重复索要；解析失败不等于未提供。只追问明确缺少的约定输入，不索要服务配置、历史案例或审批。

## 2. 检查而不重编

可核对来源、参数及口径。差异、无法识别或检查失败留在对话，不静默改值、不把未通过说成通过，也不因此创建新工作簿、回填结果文件或要求额外确认。“生成”“根据附件生成”“直接出图／Excel”均不授权现场重新编制。

通用 PDF／Excel 工具只辅助读取、核验、查看；不因通用技能要求排版或重算就修改指定交付文件。普通任务不加载架构、模板生成或其他开发文档。超出默认交付时才看 [非默认请求边界](service-execution.md)。

## 3. 原样交付

| `kind` | 唯一指定源（相对技能根目录） | 最终文件名 |
|---|---|---|
| `finished-drawing` | `.result/finished-drawings/result.pdf` | `二维成品图.pdf` |
| `control-plan` | `.result/control-plans/result.xlsx` | `控制计划.xlsx` |

输入齐全后，在宿主交付根目录（默认工作区 `outputs/`）下新建唯一任务目录，二进制复制指定源，不覆盖、不另存、不增删工作表或修改公式、元数据、格式和打印设置。不能用用户原图、模板或其他样例替代。

使用已有工具完成，不安装 Python、Excel、CAD 或其他依赖：

- 有可用 Python 时，使用 [固定交付脚本](../scripts/deliver_result.py)：

  ```text
  <可用Python> -I -B "<技能根目录>/scripts/deliver_result.py" --kind control-plan --output-root "<工作区>/outputs"
  ```

  成品图改用 `finished-drawing`。脚本自动创建唯一目录，退出码 0 且 JSON 中 `status=success`、`verified=true` 才成功；记录 `output` 为最终文件。脚本自行定位技能根目录，不需要额外传参。
- 没有 Python 时，直接使用宿主原生文件复制和 SHA-256 能力，例如 Windows PowerShell 的二进制复制与 `Get-FileHash`，或 Linux／macOS 的 `cp` 与 `sha256sum`／`shasum -a 256`。同样先建唯一目录、防覆盖、复制后比较源和目标摘要；不能因缺 Python 转去重建文档。

**源文件与交付文件 SHA-256 一致，是默认交付成功条件。** 后续查看工具不得回写；需要复核时用原生摘要比较，或固定脚本的 `--kind control-plan --verify "<最终文件>"`。结构、美观、公式或工序覆盖检查不能替代此条件。

源文件缺失、复制失败或摘要不一致时，只报告实际问题，不报成功、不链接源文件冒充新交付、不现场拼造替代品。无法完成复制／核验时如实报告。

## 4. 回复与收尾

按 [任务文件管理](task-files.md) 只清理本次临时产物，保留最终文件、用户输入与历史资料。输入齐全后当轮给最终 PDF／XLSX 链接，不再询问是否继续，不附脚本、日志、截图或差异报告。

**业务进度、工具调用前说明和最终回复均不主动讲内部实现。** 内部的复制、脚本、摘要、目录和服务状态不贴给用户；假如有异常只简单描绘本次发现的异常信息，但不做额外建议或修改。最终以 “控制计划表/成品图已备好，文件如下”加链接即可。

只有用户明确询问来源、实现、调用情况或维护技能时才据实说明，不把此例外延伸到下一项普通业务。
