# 三个工程 Tool 的目标架构

本文件供服务开发和对接时参考，记录目标架构及实现状态。当前提供文件交付、模板和 DXF 文字回填脚本，完整生成与分析能力仍需后端实现及样本验收。

## 交付与后端

普通请求按 [交付规则](execution.md) 完成资料检查与文件交付，输入齐全后当轮给文件。只有明确要求调用后端时，才按 [服务执行说明](service-execution.md) 使用下述链路。

业务 Tool 决定交付类型，文件交付不因检查异常而转向安装依赖或探测服务。服务调用失败按执行结果报告，不更换产物来源。

## 已确认的范围

| 业务 Tool | 首期能力 | 交付边界 |
|---|---|---|
| 二维成品图生成 | 草图提取或直接参数输入；基于公司 DWG 模板修改同类零件几何、尺寸标注、参数表和技术要求 | 身份信息脱敏的成品 PDF，保留制造数据 |
| 控制计划表生成 | 成品 PDF、工艺路线 Excel，结合模板、历史样例和规则 | 控制计划 Excel，有依据的字段与待确认项可区分 |
| 装配体分析 | STEP 解析及三角化、全装配或指定节点实体重叠、指定非标件出图 | 现有画布可用模型、干涉节点关系、视图与基础尺寸工程图草稿 |

先以齿轮业务验收，通用性体现为可替换的零件规则、模板、格式适配器和处理后端，不承诺第一版自动覆盖任意机械零件。装配体分析包含三个可独立调用的操作，无需将查看模型、检查干涉和出图绑成一次全量任务。

## 分层与职责

```text
内部智能体 ── 未来 HTTP MCP 接入层
                         │
                 交付规则
                 ├─ 资料检查 → .result 文件交付
                 └─ 明确调用后端的请求
                         │
              三个业务 Tool 的用例层
                         │
   文件解析 ─ 参数合并与规则校验 ─ 结果检查与交付
                         │
   参数化 CAD / PDF 导出 / Excel 生成 / 装配几何后端
                         │
           文件产物、模板版本、规则版本、参数来源

装配用例 ── 画布适配接口 ── 外部已有浏览器画布
```

- **接入层**：处理调用协议、输入引用和结果交付；HTTP MCP 属于未来包装，不把 CAD 或表格逻辑写在协议处理器中。
- **用例层**：管理三条业务流程，检查所需资料，返回成功、缺输入或能力不可用等可区分结果。可先独立于 HTTP 调用，以便测试和复用。
- **后端适配层**：封装图纸提取、同类零件参数化修改、PDF 导出及脱敏、表格生成、STEP 装配与实体运算。CAD 商业依赖与操作系统待比较，不在此锁定技术栈。
- **业务规则与模板**：将字段要求、校验条件、尺寸映射、技术条款、控制计划列映射和脱敏字段从通用流程中分离。齿轮规则只对适用零件生效。
- **产物与来源**：保留输入、模板及规则版本、字段来源、检查结果和输出引用。内部 CAD／原始文件与可交付脱敏产物区分；对外交付的汇总和文件名也遵守脱敏规则。

## 数据流与接口边界

以下为后端服务设计约定，具体工具名、字段 schema、任务机制和 HTTP MCP 协议实现尚未发布。文件交付的输入顺序及映射以交付规则为准。

1. **成品图**：草图解析与直接参数 → 字段合并 → 按规则检查缺失和冲突 → DWG 模板参数化修改 → PDF 导出及身份信息脱敏 → 检查和交付。提取不足时返回待补项，不能猜测齿形数据。
2. **控制计划**：脱敏 PDF + 工艺路线 Excel + 模板／历史／规则 → 关联工序和制造特性 → 生成控制计划 → 检查完整度及来源 → 交付 Excel。此 Tool 应可独立接受合法成品 PDF，不强制依赖 Tool 1 的私有中间文件。
3. **装配体**：STEP → 装配层级、实例变换与原始几何 → 展示网格及节点映射；干涉检查回传同一模型版本下的实例节点对；出图使用选定零件的原始几何。

三类 Tool 的输入应可表达文件引用、所选模板及业务规则；输出应包含产物引用、检查结果、未决项和来源摘要。大文件及模型通过产物引用交付，具体存储及下载方式待部署方案确定。身份脱敏后的 PDF 是 Tool 1 到 Tool 2 的约定业务交接物。

画布节点标识必须对应装配实例，不能只按零件名称或共享网格区分。模型版本变化后的旧节点选择须能被识别为失效；不得把旧选择默默指向新节点。

## 当前实现与待确认项

已有 `scripts/fill_dwg.py` 及自检，仅可做 DXF 布局文字和块属性回填；另有 `.template/finished-drawings/` 的两个 DWG、`.template/control-plans/typical.xlsx`，以及 `.result` 中的成品 PDF 和控制计划 XLSX。尚未实现本文件中的图纸解析、参数化几何、PDF 导出脱敏、控制计划生成、装配处理、任务服务或 HTTP MCP。参数化规则仍待验证。

待真实样本和接口确认：

- DWG 模板的可变几何、尺寸依赖和适用零件范围；草图识别质量及齿形提取可行性。
- 控制计划 Excel 列、历史案例匹配条件、工序规则以及资料冲突的业务优先级。
- 身份信息脱敏字段清单、替换要求和交付检查方式。
- STEP 的单位、实例及已有非标件标记情况，画布模型格式和高亮协议。
- 干涉数值容差、几何异常处理、预计文件规模及服务资源需求；非标件草稿目标样例与输出格式。
- CAD 授权与部署限制、任务执行方式、文件生命周期、HTTP MCP 的认证及调用约定。

## 后续功能验收场景

这些是实现对应能力后的验收要求，不是现有测试已通过的结论。

| 范围 | 场景与预期 |
|---|---|
| 成品图输入 | 有草图时提取后再报缺项；直接参数时完成同一数据流程；不可靠的齿形字段要求补充 |
| 几何与标注 | 输入尺寸变化后几何和尺寸标注一致，上下偏差、基准及特性标记保留；超出模板可变范围时返回不支持 |
| 模板与规则 | 缺模板、缺参数化规则或参数冲突时不宣称成品成功；替换同类模板时业务处理无需硬编码客户信息 |
| 脱敏链路 | PDF 图面、可提取文字、元数据及交付名称无指定身份信息；尺寸、公差和技术要求可供控制计划使用 |
| 控制计划 | 产品特性对应工序，控制内容有来源；规则冲突或资料缺失显式报出；输出 Excel 的单元格、公式（若有）及布局有效 |
| 装配展示 | 层级、单位和实例变换正确；同一个零件的不同实例可分别选择与高亮 |
| 干涉 | 已知穿透与不穿透样例判定正确；包围盒重叠但实体不重叠时不误报；指定节点过滤生效；无效或失败的检查不返回“无干涉” |
| 非标件 | 已有标记和显式选择均可定位；未知节点报错；原始几何生成的草稿与选定零件一致，未给设计要求不臆造 |
| 接入 | 未来 MCP 与直接调用走相同用例，错误和产物可追踪；当前回填自检不作为完整服务验收 |
