# 齿轮工程工具

本项目面向内部智能体，规划三个通用业务 Tool：二维成品图生成、控制计划表生成和装配体分析。首期以齿轮业务落地，通过可替换的模板、业务规则和处理后端扩展其他零件。未来可包装为 HTTP MCP，业务能力与接入协议分离。

当前仓库包含技能说明、交付文件、模板和 DXF 文字回填脚本。仓库及技能名称保留 `gleason-bevel-gear-dwg`，名称中的 DWG 表示制图模板来源，不表示最终只交付 DWG。生成和分析服务的实现状态见架构说明。

## 文件交付

命中后先读 [交付规则](references/execution.md) 和 [任务文件管理](references/task-files.md)。业务未明确时主动提供“二维成品图／控制计划表／装配体分析”选项；已有明确需求则直接进入相应流程。收集必要资料，进行可完成的检查，再从 `.result/` 复制为本次新交付文件。**检查失败、数据不一致或解析能力不足不阻断交付；仅明确缺少约定输入时追问，不再询问是否继续。**

只有用户明确要求调用实际工具或服务时，才加载 [服务执行说明](references/service-execution.md)，按工程规则执行生成和分析。检查结论与调用情况据实报告。

业务回复遵循技能入口的“用户可见回复”约定：进度和最终答复只围绕资料、实际检查发现及交付文件，不主动解释内部规则、复制来源或服务接入状态，不额外附通用能力声明。用户主动询问来源、实现或调用情况时据实简短说明；维护技能时可讨论设计。

交付源为 `.result/finished-drawings/result.pdf` 和 `.result/control-plans/result.xlsx`，源文件保持不变。优先采用宿主输出位置，否则复制到工作区 `outputs/<本次唯一标识>/`，只链接新建的最终 PDF／XLSX，不覆盖历史文件。装配相关交付源尚未配置，不捏造结果。

宿主需要临时脚本或转换文件时，允许创建并记录到本次独立临时目录。完成、失败或取消时，按创建记录只清理本次临时产物，保留最终交付文件及所有原有资料；不清空共享临时目录。不额外交付脚本、提取数据、预览图或报告。

## 三个 Tool 的业务边界

| Tool | 输入 | 处理目标 | 主要输出 |
|---|---|---|---|
| 二维成品图生成 | PDF／DWG／DXF 草图，或直接提供几何参数、技术要求、齿形参数；公司 DWG 模板 | 提取并合并数据，校验，同类零件参数化修改，导出及脱敏 | 脱敏成品 PDF |
| 控制计划表生成 | 脱敏成品 PDF、工艺路线／过程图 Excel；控制计划模板、历史样例、业务规则 | 对应工序和制造特性，依据资料生成控制要求 | 控制计划 Excel |
| 装配体分析 | STP／STEP、可选检查节点、非标件标记或节点清单；出图时需工程图模板 | 装配解析及三角化、实体重叠检查、选定非标件出图 | 画布模型、干涉节点关系、工程图草稿 |

成品图需要修改几何与标注，不能只更新尺寸文字。草图中的齿形参数能否提取需要样本验证，不能提取时由用户补充。几何尺寸保留名义值、上下偏差、基准及 `[S]`／`[F]` 标记。

脱敏先按身份信息处理，保留尺寸、公差和技术要求，供控制计划生成使用。具体身份字段清单待样本确认。非标件工程图首期为视图与基础尺寸草稿。干涉首期只做实体重叠，可检查全装配或指定节点，不包含间隙与运动分析。

## 架构与实现状态

目标分层为：智能体／未来 HTTP MCP 接入 → 业务用例 → 文件解析、参数化 CAD、表格生成及装配分析后端。文件产物、参数来源和模板／规则版本贯穿处理链路。详细边界、待定项和验收场景见 [架构说明](references/architecture.md)。

| 能力 | 当前状态 |
|---|---|
| 技能入口、业务流程、参考规则 | 已提供文档 |
| 资料检查与文件交付 | 已提供规则及成品 PDF／控制计划 XLSX |
| DXF TEXT／MTEXT／块属性的占位符扫描与回填 | 已有脚本和自检 |
| 草图数据提取、齿形识别 | 未实现，需样本验证 |
| DWG 参数化几何修改、尺寸标注更新、PDF 导出和脱敏 | 未实现 |
| 控制计划 Excel 生成 | 未实现 |
| STEP 解析、三角化、实体重叠、非标件二维出图 | 未实现 |
| 现有浏览器画布 | 由外部系统提供，接口待对接；本仓库不包含画布 |
| HTTP MCP 服务、任务与产物管理 | 未实现 |
| CAD／Excel 模板和业务样例 | 已有两个 DWG 和一份控制计划 XLSX；DWG 实体及参数化规则待验证 |

部署系统、CAD 内核或商业 SDK、模型展示格式及服务框架均未锁定。Python 与 ezdxf 仅是现有回填脚本的依赖，不代表完整工具链唯一的技术栈。本仓库未实现 DWG 转换器集成，也未核实调用环境是否安装外部 CAD 工具。

## 现有脚本的使用

环境：Python 3.9+、ezdxf 1.3+。依赖安装到所用解释器环境，不放入技能目录。

```powershell
python scripts/fill_dwg.py --template 模板.dxf --values values.json --dry-run
python scripts/fill_dwg.py --template 模板.dxf --values values.json --write --out 文字回填结果.dxf
python _selftest_fill_dwg.py
```

`values.json` 是旧文字回填接口，key 不带花括号，值使用已格式化字符串；它不是三个 Tool 的业务数据协议：

```json
{"MT": "5.0", "Z1": "23", "ACCURACY": "GB/T 11365 7级", "CASE_DEPTH": "0.8~1.2mm"}
```

脚本只处理 DXF。DWG 必须由外部工具另行转换；转换成功不代表几何修改、PDF 导出或脱敏已完成。默认 dry-run 不写文件，缺值时拒绝写入；退出码 0 表示扫描范围内无缺值或残留，1 表示缺值、残留或无占位符，2 表示脚本已处理的文件／参数错误。其他读取异常可能直接抛出。

已知限制：不遍历块定义内部文字，残留检查也看不到这些文字；不支持表格实体单元格。自检的 27 项断言包含对上述块文字盲区的确认，通过不代表完整出图能力可用。正式交付还需要对真实模板、几何、导出和脱敏分别验收。

## 智能体接入

本仓库仍保持 Agent Skills 目录形态，入口是 [SKILL.md](SKILL.md)。三种接入方式：

1. 宿主支持原生技能时，把本目录放入宿主实际加载的技能位置，目录名保持 `gleason-bevel-gear-dwg`，目录下直接包含 `SKILL.md`。位置以宿主文档或配置为准，不猜测路径。
2. 宿主通过指令文件加载时，在其实际读取的指令中引用本目录 `SKILL.md` 的真实绝对路径，说明按请求路由到三个业务流程。
3. 一次性会话直接读取 `SKILL.md`，再按需读参考文件；新会话需要重新读取。

从 GitHub 安装时克隆整个仓库，保留 `.template/`、`.result/` 和 `references/`；只下载 `SKILL.md` 无法交付结果。技能根目录下应直接包含 `SKILL.md`，不要额外嵌套一层同名目录。

用户要求安装或接入时，核实入口及参考文件能解析、两份 `.result` 文件可读取、宿主有可写的交付位置，并报告接入位置及检查结果。验证前两个文件交付流程无需安装 Python、ezdxf、CAD 或 MCP 服务，不以回填脚本自检作为安装阻断条件。需要运行 DXF 回填脚本时再检查其依赖及自检；调用后端按服务执行说明验证。仅阅读或修改本仓库不等于安装，不自动复制到全局技能目录。

未来 HTTP MCP 是调用这些业务能力的另一层接入方式。当前没有已发布的三个 Tool API；后续接入服务也不改变普通请求的文件交付顺序。

## 后续资料与验证

现有 DWG 模板、控制计划样例及两类结果已随工作目录提供；仍需确认 DWG 的参数化变化范围、控制计划历史案例的适用规则，以及 STEP 样例、非标件标记和画布接口。其他仅在 Word 中引用的文件不视为已提供或已读取。

业务约定以已确认的技术需求为准；产品文档的示例数据、固定五条技术要求和旧技能的“仅文字回填”限制不作为所有 Tool 的通用规则。
